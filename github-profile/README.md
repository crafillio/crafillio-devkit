## API Devkit

**REST, gRPC, S3, workflows and load testing — in one offline-first desktop app.**

Most teams keep three tools open: one for HTTP, one for gRPC, and a browser tab for buckets. Then a
fourth when someone asks how fast it is. API Devkit puts all four behind one tab strip, one set of
environment variables and one collection format — and never sends your data anywhere.

### What's in it

- **REST** — five body kinds including multipart with file parts, three auth schemes, and redirects
  followed manually so you see the whole hop chain, not just the final response
- **gRPC** — server reflection or `.proto` files, all four call types, editors prefilled from the
  schema with enums as names and `int64` as strings so nothing is lost through JSON
- **S3** — browse, upload, download, batch and recursive delete, presigned URLs, and metadata
  editing that doesn't silently drop the headers you didn't mention
- **Workflows** — a drag-and-drop canvas where REST and gRPC steps mix freely, so you can
  authenticate over HTTP then call a gRPC service with the token you got back
- **Load testing** — ramp-up, RPS ceiling, error-rate circuit breaker, and percentiles from a
  reservoir sample so long runs keep flat memory without discarding the tail
- **Reports** — a run renders as one self-contained HTML file or PDF, reproducing the canvas you
  drew, every request and response, and any file produced, embedded so it downloads from the page

### How it behaves

| | |
|---|---|
| **Offline by default** | No telemetry, no analytics, no update ping, no account |
| **Your data, your disk** | Collections are plain JSON in your home directory; secrets are encrypted before they touch it |
| **Honest numbers** | A 4xx counts as a failure in a load test — reporting it as success would hide a broken target |
| **No silent failure** | An undefined variable is reported, never replaced with an empty string |
